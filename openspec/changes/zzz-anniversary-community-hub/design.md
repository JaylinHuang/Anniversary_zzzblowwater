## Context

本项目从空仓库起步，服务对象是一个因《绝区零》结缘的 QQ 群（近一周年）。需要同时满足：① 周年庆仪式感与好玩互动；② 群聊记忆可沉淀；③ 周年后可持续扩展。QQ 官方不提供面向第三方网站的群聊历史开放 API，因此「调取聊天记录」必须以**群内授权 + 导入/机器人桥接**实现，不能假设可直接 OAuth 拉全量历史。

利益相关方：建站负责人（你）、群管理、普通群友。

## Goals / Non-Goals

**Goals:**

- 交付可上线的 Web 社区站（PWA），模块化，便于后续加活动/玩法。
- 首发打通：首页氛围、群友图鉴、回忆时间线、祝福墙、基础活动、图库、聊天记录导入与趣味统计。
- 交互有「游戏感」：扭蛋、签文、群梗问答、时间胶囊、合作拼图等。
- 隐私可控：默认脱敏、管理员审核、成员可申请隐藏/匿名。

**Non-Goals:**

- 首期不做微信小程序原生版（可预留 API，二期用同一后端适配）。
- 不做未授权的群聊爬取或对外公开全量聊天。
- 不做官方游戏账号绑定/抽卡模拟器级复杂系统（可作后续插件）。
- 不依赖必须实时在线的 QQ 机器人才能上线（机器人是增强通道）。

## Decisions

### 1. 形态：Web 优先 + PWA，小程序二期

- **选择**：Next.js（App Router）+ TypeScript 全栈，部署为响应式站点并支持「添加到主屏幕」。
- **理由**：扩展成本低、分享链接方便、同一套 API 日后可给小程序用。
- **备选**：纯 Vite SPA + 独立后端；微信小程序优先——分享弱于 Web、审核与能力受限，不适合作第一版「持续扩展」主战场。

### 2. 数据与模块边界

- **选择**：核心域拆为 `members` / `timeline` / `chat` / `wishes` / `games` / `events` / `media` / `admin`；前端按路由懒加载模块。
- **理由**：周年后可独立迭代某一玩法而不动全局。
- **备选**：巨型单体页面——短期快，长期难维护。

### 3. 群聊记录：导入优先，机器人可选

| 通道 | 说明 | 阶段 |
|------|------|------|
| A. 文件导入 | 管理员导出 QQ 聊天记录（TXT/HTML 等），上传解析入库 | **MVP 必做** |
| B. 机器人桥接 | OneBot/NapCat HTTP 上报 → `/api/webhooks/onebot`（`ONEBOT_ACCESS_TOKEN` + 可选 `ONEBOT_GROUP_ID`），写入 `onebot-live` 批次 | **已实现** |
| C. 人工精选 | 管理后台「金句/梗」投稿与审核 | MVP 同步做 |

- **脱敏规则**：手机号/链接/身份证等模式替换；可配置「仅展示精选」「统计匿名化」「某人消息不可检索」。
- **备选**：只做人工精选——安全但失去「一年记忆」规模感。

### 4. 身份与权限

- **选择**：**整站口令墙**（群共享口令）+ 进入后自选昵称建立成员会话；可选 QQ 号自填绑定（非 OAuth）；角色：`guest`（未过口令） / `member` / `moderator` / `admin`。
- **理由**：QQ 开放平台登录对个人站门槛高；口令门槛足够挡住路人；已确认整站不开放游客只读。
- **备选**：完全开放游客写——易刷屏；强制 QQ 互联——首期不现实。

### 4b. 周年日期（已确认）

- **建群/正日周年**：每年 **7 月 10 日**（同行天数以此为锚点）。
- **今年庆典活动日**：因特殊原因推迟至 **8 月 4 日**；首页倒计时默认指向最近一次庆典日（今年为 2026-08-04）。

### 5. 视觉与交互方向（周年「新艾利都夜生活」）

- **选择**：暗色都市霓虹基调（青/琥珀/雾灰，避免默认紫渐变）；首页全幅主视觉 + 倒计时；微动效（入场、扭蛋、时间线滚动）。
- **交互亮点**：
  - **群友扭蛋**：随机抽出一位群友名片 + 一句 TA 的金句（来自归档）。
  - **时光卷轴**：纵向时间线，节点可展开成「当时群聊切片」。
  - **合作拼图**：每人每天可点亮一块，拼出周年主视觉。
  - **群梗考试**：管理员出题，答对解锁徽章。
  - **时间胶囊**：写给「明年今日」的信，到期站内解锁。
- **备选**：纯静态相册页——仪式感不足。

### 6. 存储与部署

- **选择**：首期 **SQLite**（便于国内单机 VPS/Docker 部署）+ 本地/对象存储图床；面向国内服务器，避免强依赖海外 Serverless。
- **聊天检索**：消息表 + SQLite FTS5。
- **聊天数据**：由管理员导出，可拿到接近完整的一年记录 → 导入管道按「大批量分批」设计。

## Risks / Trade-offs

- [QQ 导出格式不一 / 解析失败] → 先支持 1～2 种常见导出；提供预览校验与失败行报告。
- [隐私争议] → 群公告知情同意；默认统计匿名；个人可申请「不参与图鉴/榜单」。
- [功能过多导致做不完] → MVP 切三层：仪式壳 → 记忆归档 → 1～2 个王牌玩法；其余排期。
- [机器人运维成本] → 明确二期；MVP 不阻塞上线。
- [版权/同人素材] → 图库仅群内可见；标注非官方、禁止商用传播。

## Migration Plan

1. 搭平台核心与邀请码，部署空壳首页。
2. 录入种子成员与时间线里程碑（可不依赖聊天导入先上线）。
3. 试导入一小段聊天 → 校验脱敏与统计 → 再导入全年。
4. 开放祝福墙与 1 个互动玩法做周年当天高潮。
5. 周年后开启活动中枢与模块插件位，按需加机器人同步。

回滚：各模块功能开关（feature flag）；导入批次可按 `import_batch_id` 整批撤销。
